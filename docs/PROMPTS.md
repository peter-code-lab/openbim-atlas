# The openBIM Atlas — AI Prompt Log

The Atlas website is generated by **Claude (Anthropic's Claude Code agent)**, directed
by Kyle through the prompts below. Logged per the team's documentation rule:
*"document the code if coded, or AI prompts if created by other than human agents."*
A copy of this document belongs in the shared project folder (Google Drive / Dropbox).

Each entry gives the direction Claude received (condensed but faithful to the original
wording) and what it produced. The tool itself is documented in `docs/TOOL.md` in the
repository; the data sources in the companion *Source Register* document.

---

## v0.1 — first mockup (relayed collaborator brief)

**Prompt:** "This is the website done by an organization which outlines BIM mandates
status of 59 jurisdictions… what we can do differently is more about integrating data
and show correlations… Do you think you can already start to mock up something? For
example, a world map as the background, one layer with openBIM metrics, another layer
with openBIM mandates, etc. …the most important thing to separate us from [the
existing tracker]: what we can do differently is more about integrating data and show
correlations."

**Produced:** A self-contained HTML prototype — stylized dot-matrix world map,
mandate-stage layer, illustrative "maturity" metric layer, and a first correlation
panel (strip plot of maturity by mandate stage).

## v0.2 — real borders, real deck data

**Prompt:** "The dots are not representative of countries at all — make this a world
map with the borders colored in, like the website. Use the information from the
PowerPoint (*Some openBIM business value and mandates examples*). The score system
isn't working for me. When choosing a region, zoom into the map. Explain what
maturity / mandates / integrated mean — what is the correlation and the main items
we're trying to show?"

**Produced:** A choropleth with real country borders (Natural Earth geometry);
mandates split into the deck's two dimensions (public procurement vs permit
submission & approvals); the invented maturity score replaced by the deck's
documented business-value cases (buildingSMART Awards); animated region zoom;
a three-step explainer (Policy → Practice → The Link) and a counted correlation
panel.

## v0.3 — source everything

**Prompt:** "For each country, source every single country. As soon as you're done
you can take away the prototype-data [warning]. After researching all the countries,
also provide primary sources for where you got your information. Where do you get
documented value as well? This should also be sourced better."

**Produced:** A web-research pass over all jurisdictions (four parallel research
agents); every mandate claim linked to a source with a confidence flag (official /
secondary / needs-verification); statuses corrected against primary documents
(e.g. Spain Apr 2024, Denmark 2013, Finland permit mandate Jan 2026, Czechia BIM Act
2027, Russia PP 331 reclassified as statutory); value cases linked to bSI Awards
announcements and yearbooks; the prototype-data banner replaced by an as-of note.

## v0.4 — SBI branding, projection, documentation (PacTime feedback via Janice)

**Prompt:** "[1] Instead of the current projection, consider Mercator or Goode's
Homolosine or Winkel because it looks good and is fun to say. [2] Show us how to
input the data and document that; also document the tool itself — the code, or the
AI prompts if created by other than human agents. [3] Use SBI colors & fonts if
possible, like Century Gothic — see sbi.international. Keep zooming quality for
looking clearly at Africa or Europe. I want the SBI branding to look just like the
website."

**Produced:** Winkel Tripel projection over sharper (50 m simplified) geometry; SBI
visual identity (green gradient headings, Century Gothic font stack, validated green
map ramp, blue value markers for color-blind safety); `docs/DATA-GUIDE.md` and
`docs/TOOL.md`; page retitled to the workshop framing *"The openBIM Atlas: Where
Mandates Meet Business Value."*

## v0.5 — team review comments

**Prompt (condensed from the comment list):** "Create shared-folder documents listing
the AI's data sources and the Claude prompts. Hyperlink the source labels in the
metric boxes and make source styling consistent. Fix inconsistencies between the map
detail cards and the case cards (e.g. smartBRIDGE '10,000+ IFC objects'). Explain or
visualize the correlation more intuitively. Categorize metrics into project-outcome
vs process metrics (process metrics are less impactful). Think about a fact-checking
workflow. Why list countries that are 'None tracked / None tracked'? FYI: for FHWA
ADCMS, only IDOT and PennDOT run IFC/openBIM projects, no outcome metrics yet."

**Produced:** This document and the *Source Register* (upload-ready for Google
Drive); hyperlinked, uniformly styled sources everywhere; detail cards now always
include the headline metric; a paired-distribution correlation chart ("share of
jurisdictions" vs "share of value cases" per mandate stage) with a plain-language
explanation; outcome/process metric chips with outcome-first ordering; none-tracked
jurisdictions moved out of the Atlas into the Source Register's research log; the
IDOT/PennDOT note added to the United States entry; a verification-workflow proposal
added to `docs/DATA-GUIDE.md`.

## v0.6 — Morocco deep-dive

**Prompt:** "Send more agents to look into Morocco since there should be openBIM there
— there is a buildingSMART chapter there already."

**Produced:** Two additional research agents (chapter/ecosystem + French- and
Arabic-language policy sources). Morocco restored to the Atlas as *Partial / phasing
in* on procurement (ONCF requires BIM across the LGV Kenitra–Marrakech extension,
Medias24 2026; a blog-reported ministry circular with a phased 2025→2030 mandate
could not be verified in official sources and is flagged as such), permits *None
tracked* (Rokhas.ma e-permitting is document-based). New "openBIM ecosystem" section
on country cards, seeded with buildingSMART Morocco (first African bSI chapter, 2022;
Marrakesh Summit 2024; bSI certification), IMANOR's NM ISO 19650-1 adoption, and the
A7 highway IFC O&M research case. Source Register regeneration moved into the repo
(`tools/gen-sources.js`).
